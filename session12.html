Semantic Segmentation & CV Metrics

Turn a CNN that maps an image to a class vector into one that maps an image to a class at every pixel. Then measure how good those pixels (and, for detection, boxes) are: IoU, precision, recall, and mAP.

▶ From the recording

“If I have pooled, I’ll unpool. If I have convolved, I’ll do transpose convolution. Mathematically deconvolution does not exist — we call it that anyway. In segmentation we generally use transpose convolutions.” Skip connections (ResNet residuals, U-Net copies) “smooth the lost topology” so gradient descent can actually find a minimum.

CNN recap

A convolutional net is a function of the image parameterised by filter weights and biases. We design the form (conv → nonlinearity \(f(\cdot)\) → pool, repeated) and fit the parameters to data. A classifier CNN collapses \(H\times W\times C\) to an \(F\)-dimensional vector of class scores. Questions that need a map, not a vector: which pixels are the cat? how far is each pixel from the camera? which pixels are fake?

Semantic segmentation as per-pixel classification

Predict an \(F\)-dimensional probability vector at every pixel. Loss is computed and back-propagated at every pixel. Visualise by colouring each pixel with \(\arg\max\) over classes. “Semantic” here just means we are naming things — and we do not distinguish object instances (two cars are the same class colour).

◆ From vector to image

Any vector–vector map can be rewritten as \(1\times1\) convolutions. Take a classifier CNN, replace the final fully-connected layers with \(1\times1\) convs, and it becomes a fully convolutional net that accepts any spatial size and emits a coarse label map. Long et al., Fully Convolutional Networks for Semantic Segmentation, CVPR 2014.

Encoder–decoder / FCN

Key idea: downsample toward the middle of the network (convolutions, pooling — large receptive field, cheap), then upsample back to input resolution. Because everything is convolution, you can reuse an ImageNet classifier as the encoder: feed a bigger image and the same weights produce a bigger feature map.

How do we upsample?

OpWhat it does
Nearest-neighbour unpoolInverse of \(2\times2\) max-pool: copy each value into a \(2\times2\) block (e.g. 8 becomes four 8s).
Max-unpoolRemember argmax switches from the encoder; put the value back in that slot, zeros elsewhere — sharper.
Transpose convolution“Fractionally strided” conv: each input multiplies a filter that is added into a larger output. Learnable upsampling. (Also called deconvolution, which is a misleading name.)

A \(3\times3\) convolution, stride 2, pad 1 downsamples. A \(3\times3\) transpose convolution, stride 2, pad 1 upsamples — the output is the filter, weighted by each input activation, tiled with overlap.

U-Net

Ronneberger et al., MICCAI 2015 — originally for biomedical images, now the default encoder–decoder. The “U”: a contracting path (downsample) and an expanding path (upsample) with skip concatenations that copy high-resolution encoder feature maps onto the matching decoder stage. That preserves localisation that pooling would otherwise destroy.

Handout segmentation metrics

  • Pixel accuracy — fraction of pixels correctly labelled. Inflated by huge classes (sky, road).
  • mIoU — IoU averaged over classes; the number that actually punishes missing the small object.
  • Boundary error — ABPE / BDE: how far predicted contours sit from ground-truth contours (localisation of the outline, not just the area).

Intersection over Union

For a class (or a box), compare the predicted set \(P\) to ground truth \(G\):

\[ \mathrm{IoU} = \frac{|P\cap G|}{|P\cup G|} = \frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}+\mathrm{FN}} \]

Mean IoU averages this over classes. For detection, a predicted box is a true positive if \(\mathrm{IoU}\ge\) a threshold (PASCAL: 0.5). Multiple detections of the same object: first is TP, the rest FP.

\[ P=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}}\,,\quad R=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}}\,,\quad F_1=\frac{2PR}{P+R} \]

Precision = “of my predictions, how many were right?” Recall = “of all the true objects, how many did I find?”

▲ Don’t use accuracy for detection

A detector that says “no object” everywhere scores ~99% accuracy on a typical image (almost every window is background). Accuracy is the wrong metric when positives are rare — hence precision/recall, IoU and mAP.

Average Precision and mAP

Rank all detections of one class by confidence. Walking down the list, precision zig-zags (drops on an FP, rises on a TP) while recall is non-decreasing. AP is the area under the precision–recall curve. In practice we first make the curve monotone: at each recall \(\hat{r}\), replace precision by the max precision for any recall \(\ge\hat{r}\).

PASCAL VOC 2008 11-point interpolated AP: average the interpolated precision at recall \(0, 0.1, \ldots, 1.0\). mAP = mean of AP over classes. (COCO later averages over IoU thresholds 0.5:0.05:0.95 as well.) A full walk-through is in Session 16.

Mini numerical — IoU of two boxes. GT box \([x_1,y_1,x_2,y_2]=[0,0,4,4]\), prediction \([1,1,5,5]\).

Key takeaways

◆ Remember these
  • Semantic seg = F-way softmax at every pixel; FCN = classifier with FC replaced by \(1\times1\) conv.
  • Upsample with unpool or transpose convolution. U-Net adds skip concatenations for localisation.
  • \(\mathrm{IoU}=|P\cap G|/|P\cup G|\). TP if IoU ≥ threshold (often 0.5).
  • P / R / F1 from the confusion matrix. AP = area under (interpolated) PR curve; mAP averages AP over classes.
