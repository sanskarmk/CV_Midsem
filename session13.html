Object Detection — R-CNN family & YOLO

Not just “what is in the image” but where — a class label and a bounding box for every object. Sliding windows explode combinatorially; region-based CNNs and then single-shot detectors (YOLO) made it practical.

Worked the sliding-window count live: a 40×20 template on a duck image → 330 windows, 6 positives — “off the bat, from a classical ML perspective, lots of unnecessary negatives.” Region proposals exist to stop scoring empty water. On IoU: “the closer to 1 the better, closer to 0 the worse — this is the sort of problem statement you can expect in your semester exams.” YOLO lecture: v1 = 7×7 grid, two boxes per cell; “YOLO v2 used anchor boxes, but that is not within the scope of your syllabus.” Faster than Faster R-CNN, less accurate; real-time is the pivot.

Detection vs segmentation

Object detection locates and classifies objects by drawing a bounding box around each one. Segmentation assigns a class (or instance ID) to pixels. Detection is the box problem; instance segmentation (Mask R-CNN) does both.

Sliding windows — and why detection is hard

Naive recipe: try every sub-window, at every position and scale, and classify it (“is this a tight box around a pedestrian?”). For a template of size \((b_y, b_x)\) on an \(H\times W\) image there are already \((H/b_y)\times(W/b_x)\) boxes — before extra scales \((b_y s, b_x s)\) and aspect ratios. Four ways to get a box wrong: left \(x\), right \(x\), top \(y\), bottom \(y\).

◆ Smarter than a random-number generator?

Guessing a 1k-way class is \(1/1000\). Guessing all four box corners within 10% of image size is \(1/10^4\). Both: \(1/10^7\). Detection is combinatorially harder than classification, and positives are extremely rare — almost every window is background. Always compare a detector against “guess” or “always the majority label.”

Classic pre-CNN: HOG + sliding window + linear SVM for pedestrians (Dalal & Triggs, CVPR 2005). PASCAL VOC: 20 classes (aeroplane, bicycle, bird, boat, bottle, bus, car, cat, chair, cow, dining table, dog, horse, motorbike, person, potted plant, sheep, sofa, train, tv). COCO (2014): 80 categories, much harder (best mAP in the lecture’s era ~52%).

Evaluating boxes

Standard overlap: IoU / Jaccard \(= |A\cap B|/|A\cup B|\). A detection is correct if IoU with a ground-truth box ≥ threshold (PASCAL: 0.5) and the class matches. Accuracy is useless: saying “no person” everywhere is ~99% accurate. Use precision–recall and mAP (Sessions 12 and 16).

R-CNN — regions + CNN features

Girshick, Donahue, Darrell, Malik, CVPR 2014. Don’t slide a CNN over millions of windows. Propose ~2000 candidate boxes with Selective Search (a segmentation-based grouping), then classify those.

Propose
~2000 region proposals per image (Selective Search).
Warp + CNN
Warp each region to a fixed size, run AlexNet (pre-trained on ImageNet 1000-way, fine-tuned on PASCAL 21-way including background). Take fc7 activations (4096-D).
SVM + box regression
Linear SVM per class. A bounding-box regressor refines the proposal. Hard-negative mining: negatives are proposals with 20–50% overlap, plus iterative retraining on the worst false positives.

PASCAL 2010 mAP: 53.7% vs 35.1% Selective Search and 33.4% DPM — a step-change. Pros: accurate; any CNN backbone plugs in. Cons: three ad-hoc losses (softmax fine-tune, SVM hinge, L2 box regression); training ~84 h and lots of disk; inference ~47 s/image (VGG16) because the CNN runs 2000 times.

Fast R-CNN and Faster R-CNN

Fast R-CNN (Girshick 2015): run the CNN once on the whole image. For each proposal, RoI pool (later RoI align) crops the corresponding region of the feature map to a fixed grid (e.g. 7×7), then a small head predicts class and box. One network, one loss, much faster.

RoI geometry example from the slides: image \(H=600, W=800\), feature map \(6\times8\), box \((x,y,w,h)=(50,150,250,350)\) maps to \((0.5, 1.5, 2.5, 3.5)\) on the feature map — then that crop is resized to 7×7.

Faster R-CNN (Ren, He, Girshick, Sun, NeurIPS 2015): throw away Selective Search. A Region Proposal Network (RPN) is a small conv net on the shared feature map that, at each location, scores \(k\) anchors (object / not) and regresses box deltas. RPN + detector share the backbone — proposals become almost free. This is the two-stage template everything since has riffed on.

Mask R-CNN

He, Gkioxari, Dollár, Girshick, ICCV 2017. Add a small FCN head on each RoI that predicts a binary mask. Everything (class, box, mask) is learned together. That is instance segmentation. Same idea extends: if you can associate a quantity with a box and have data, you can train a head for it (PlaneRCNN predicts 3D planes from one RGB image).

YOLO — You Only Look Once

Redmon, Divvala, Girshick, Farhadi, CVPR 2016. No proposals. Split the image into a \(7\times7\) grid; at each cell predict class scores + 2 bounding boxes (and a confidence). One forward pass. ~7× faster than Faster R-CNN, worse accuracy/precision, immensely popular in robotics. Follow-ups: YOLOv2, v3, … (SSD is a sibling single-shot family).

◆ Two-stage vs one-stage

Two-stage (R-CNN family): propose, then classify/refine — slower, usually more accurate, better on small objects. One-stage (YOLO, SSD): dense predictions on a grid — real-time, a bit less precise. The exam question is almost always “why was Faster R-CNN better than R-CNN / Fast R-CNN?” or “YOLO vs Faster R-CNN.”

Mean-shift detection, multilabel, skin

Mean-shift as a detector (handout, contact session 10): run mean-shift on a colour / back-projection map and take modes as object centres — no sliding window, no CNN. Same climb-to-mode idea as segmentation; here each mode is a detection. Cheap, breaks when colour is not distinctive.

Multiclass vs multilabel. Multiclass: one label per image/box, softmax (mutually exclusive). Multilabel: several labels can be true at once (a photo is “beach” and “person”), independent sigmoids. Detection is closer to multilabel at image level (many objects) and multiclass per box. Object localisation → multilabel classification in the handout is: find the box, then attach every tag that applies.

Skin detection (handout use case): a pixel-wise colour classifier (thresholds in HSV/YCbCr, or a small CNN) that marks skin. Used as a fast proposal for faces/hands, or as a safety/moderation filter. Lighting and ethnicity shift the colour cluster — that’s why HSV (decouple brightness) beats raw RGB, and why a learned model beats a fixed threshold.

Key takeaways

◆ Remember these
  • Detection = class + box. Sliding windows explode; accuracy is the wrong metric.
  • R-CNN: 2000 Selective Search crops × CNN × SVM. Accurate, ~47 s/image.
  • Fast: share convs + RoI pool. Faster: learn the proposals (RPN + anchors).
  • Mask R-CNN = Faster + mask head. YOLO = no proposals, \(7\times7\) grid, real-time.
