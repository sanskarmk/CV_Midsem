Exam Prep · theory only, no numericals

Post-midsem theory, in two hours

Everything after the midsem, organised the way the exam will ask for it. Each topic follows the same five beats — the problem → the idea → why it works → where it breaks → what replaced it — because that chain is the answer to a design question. Memorising definitions gets you 40%; being able to say why the previous method failed gets you the rest.

◆ The one thing to internalise

The whole post-midsem syllabus is a single story told four times: someone builds a method, it hits a bottleneck, the next method removes exactly that bottleneck and inherits a new one. Classification, segmentation, detection and tracking are four runs of that same loop. If you can name the bottleneck at each step, you can answer any case study — because a case study is just "given this constraint, which point on the chain do you stop at?"

0 · The spine

◆ Understand it

Three questions, in increasing difficulty. What is in this image? — classification, one label per image. Where is it? — detection (a box, coarse) or segmentation (a pixel mask, exact). Where is it going? — tracking, across frames.

Each question costs more than the last. Classification maps an image to one label. Detection must produce a class and four coordinates simultaneously — if your class accuracy is 1-in-1000 and each coordinate is 1-in-10⁴, the joint probability of being right collapses. That compounding is why detection needed a decade of architectures and classification did not.

✦ Design instinct

Choosing between them is a use-case question, never a technical one. Does the answer need an area or a boundary? Segmentation — tumour size, defect area, drivable surface. Does it need presence and rough position, fast? Detection — obstacle ahead, person in the cell. Does the same object need identity across time? Tracking. Getting this choice wrong costs more marks than getting the architecture wrong.

1 · Image classification Session 9

◆ The problem

Map an image to a discrete label. Sounds easy; it is not, because the same object produces wildly different pixel matrices under illumination change, deformation, occlusion, background clutter, viewpoint change, scale change and intra-class variation. A classifier must be invariant to all of them while staying sensitive to the thing that actually distinguishes classes. That tension is the whole problem.

The three attempts, in order

Nearest neighbour
Idea: memorise every training image; classify by distance (L1 or L2) to all of them, majority-vote over k. Why it fails: the cost structure is backwards — O(1) to train, O(N) to predict, when deployment needs the opposite. And raw pixel distance is not semantic distance: shift the image a few pixels, mirror it, or change the lighting, and the distance explodes while the content is unchanged. On CIFAR-10 it reaches only ~20%.
Linear classifier
Idea: stop memorising, learn parameters. Flatten the image, compute scores = Wx + b. Three ways to read it: algebraically as scores, visually as one learned template per class, geometrically as hyperplanes cutting the feature space. Why it fails: "one template per class" is the fatal phrase. A horse facing left and a horse facing right must share one template, so the template becomes a blurry two-headed average. And a hyperplane cannot separate XOR or concentric circles — no linear boundary exists. Roughly 40% on CIFAR-10.
CNN
Idea: learn a hierarchy of features rather than one template — edges, then textures, then parts, then objects — with nonlinear activations between layers so the decision boundary can bend. Why it works: weight sharing gives translation tolerance for free, and depth buys nonlinearity. LeNet-era CNNs jumped CIFAR-10 to ~55–58%.
◆ The transferable insight

The progression is memorisation → single linear template → learned hierarchy. The same progression appears again in segmentation (thresholding → k-means → learned encoder) and in detection (template matching → learned proposals). When a case study asks "why not just use a simpler method," the answer is almost always one of these three failures: cost at inference time, one-template-per-class rigidity, or an inability to represent a nonlinear boundary.

Supporting theory you should be able to state

Binary vs multi-class vs multi-label
Sigmoid + binary cross-entropy for one yes/no. Softmax + cross-entropy for one-of-N — softmax outputs are the per-class confidence scores everything downstream uses. Multi-label is staged: detect the object, then classify its subtype (dog → breed, defect → defect type).
Why train/val/test, not train/test
If you tune hyperparameters on the test set, the test set has leaked into the model and no longer estimates generalisation. Validation absorbs the tuning; test is touched once. k-fold cross-validation exists because a single split may be unrepresentative — each fold should be a representative subsample of the population.
Bag of Visual Words
The pre-deep-learning pipeline: detect keypoints (SIFT), describe them, build a histogram of visual words, feed the histogram to an SVM or random forest. Worth knowing as the thing CNNs replaced — it turned an image into a fixed-length tabular row so that classical ML could be applied at all.
Regularisation
L2 penalises large weights, reducing overfitting. In the margin-based (SVM) view, the margin is the tie-breaker between many hyperplanes that all achieve zero loss — it picks the one that generalises.

2 · Attention, Transformers, Vision Transformers Session 10

◆ The problem it was invented for

An encoder–decoder compresses an entire input sequence into one fixed context vector, and every decoder step reads that same vector. Two consequences: an information bottleneck (a 50-word sentence and a 5-word sentence get the same budget), and uniform weighting (every input token contributes equally to every output token, which is nonsense — translating "bank" needs the words near it, not the whole paragraph). LSTMs mitigate long-range forgetting but do not remove the bottleneck.

Attention — the fix
Give every decoder step its own context vector. Score the decoder's current state against every encoder state (dot product), softmax the scores into weights, and take the weighted sum. The weights are learned. Now step 3 can look mostly at input token 7 while step 4 looks elsewhere.
Self-attention — the generalisation
Drop the encoder/decoder distinction and let a sequence attend to itself. Each token emits a Query (what am I looking for), a Key (what do I offer) and a Value (what I actually pass on) via learned projections. Attention = softmax(QKᵀ/√dk)·V. The √dk scaling keeps the dot products out of the saturated region of the softmax.
Why it beat RNNs
Parallelism. Recurrence forces sequential computation; attention computes all pairwise interactions at once. That, plus a much larger effective context window, is the entire practical argument.
The block
Self-attention → residual connection → layer norm → feed-forward MLP → residual → norm, stacked. Residuals smooth the loss landscape and keep gradients alive through depth. Multi-head attention runs several attention operations in parallel with separate Q/K/V projections, so different heads can specialise; the heads are learned, not assigned.
Positional embeddings
Attention is permutation-invariant — it has no idea what order the tokens came in. Position must be injected explicitly (absolute, relative, or rotary/RoPE). Remember this: it is the reason ViT works at all.

Vision Transformer

◆ The one idea

Cut the image into fixed patches (16×16), flatten each patch into a vector, linearly project it into an embedding — now a patch is a token and the entire text machinery applies unchanged. Add positional embeddings so the model knows where each patch sat, prepend a classification token, run the transformer, read the class off the head.

The deep consequence: transformers are modality-agnostic. Once anything — text, image, audio, video — is embedded into tokens, the same architecture consumes it. That is why multimodal models exist at all, and it is the intuition behind CLIP and VLMs.

✖ Where ViT breaks — and this is the design question

A CNN has built-in priors: locality (nearby pixels matter to each other) and translation equivariance (a cat is a cat wherever it appears). A ViT has neither — it must learn them from data. So ViTs are data-hungry: with modest data a ResNet wins; past a large pre-training threshold the ViT overtakes it, because it was never constrained by the priors in the first place. They are also compute-expensive.

The exam answer: ViT for general-purpose representation at scale with pre-training available. CNN-based specialists (YOLO, Faster R-CNN, U-Net) for a specific task under data or compute constraints. A generalist does not beat a specialist on the specialist's own task.

3 · Classical segmentation Session 11

◆ Framing

Segmentation is per-pixel classification. Three flavours: semantic (label each pixel by class, all cars are "car"), instance (separate car 1 from car 2 — you can count), panoptic (both: countable "things" plus uncountable "stuff" like road and sky).

The theoretical grounding is Gestalt psychology — the study of why humans group things. Its laws are the assumptions every classical algorithm encodes: proximity (near things group), similarity (alike things group), common fate (things moving together group — this is the bridge to video), continuity, closure (we complete occluded boundaries), common region, symmetry. Grouping can be bottom-up (pixels group because they look alike) or top-down (pixels group because they belong to the same known object).

The chain of four, each fixing the last

1 · Histogram thresholding
Idea: plot the intensity histogram, find the modes, split at the valleys. Breaks because: a histogram has no spatial information — two completely different images can have identical histograms. The number of modes is arbitrary, noise creates spurious peaks, and pixels near the boundary get misassigned. Smoothing helps only a little.
2 · k-means
Fixes: gives you an actual clustering procedure instead of eyeballed valleys. Treat each pixel as a point in RGB space, initialise k centroids, assign to nearest, recompute, repeat. Breaks because: k is a hyperparameter you cannot derive; assignment is hard (a pixel is fully in one cluster); the decision boundaries are piecewise-linear, so it cannot model curved or elliptical regions; and, crucially, still no spatial term — the same green in a tree and in the grass lands in one cluster.
3 · GMM with EM
Fixes: soft assignment and non-linear boundaries. A generative model — the image is assumed to be a mixture of Gaussian blobs with means and covariances. E-step: given the current blobs, compute each pixel's responsibility (probability of belonging to each blob). M-step: given the responsibilities, re-estimate the blobs. Iterate. Elliptical clusters of different shapes and sizes become representable, and outliers get low probability rather than a forced label. Breaks because: you still choose the number of components by hand, you additionally have to choose the generative family, and it is slow. (Derivations and numericals here are explicitly out of syllabus — know the E/M intuition, not the formulas.)
4 · Mean-shift
Fixes: both remaining problems at once. (a) Augment the feature space from (R,G,B) to (R,G,B,x,y) — position becomes part of the feature, so the tree-green and grass-green finally separate. This is literally positional encoding, the same trick as in transformers. (b) Seed many kernel density estimators across the space and let each climb to its local mode; trajectories converging to the same peak define a basin of attraction, and the number of basins is the number of clusters — so k is discovered, not chosen. Breaks because: bandwidth h is now the sensitive hyperparameter (too small = expensive and over-segmented, too large = no convergence), and a histogram over a high-dimensional feature space is infeasible — hyperspectral, LiDAR and X-ray data kill it.
◆ Why this chain is worth memorising

It is the cleanest example in the course of bottleneck-driven design, and every step names its own successor. Thresholding lacks a procedure → k-means. k-means is hard and linear → GMM. GMM needs k → mean-shift. Mean-shift dies in high dimensions and needs hand-crafted features → deep learning. A hybrid also exists in practice: run mean-shift to discover the number of modes, then feed that k to k-means or GMM.

4 · Deep segmentation and U-Net Session 12

◆ The architectural problem

A classification CNN outputs 1×1×F — one vector for the whole image. Segmentation needs H×W×F — a full-resolution prediction. But the CNN's whole mechanism is reducing spatial dimensions to build semantic abstraction. So you need a network that goes down and then comes back up: an encoder–decoder.

Downsampling — the encoder
Convolutions (valid padding shrinks; same padding preserves), strides (bigger stride = faster, less information, important for edge inference), and max pooling. Each stage trades spatial resolution for semantic depth: edges → textures → parts → objects.
Upsampling — the decoder
Unpooling either duplicates neighbours or writes values back at remembered max locations and zero-fills the rest — disliked, because storing positions costs memory and zero-filling destroys data. Transpose convolution is the learned alternative: instead of sliding a kernel over the image, every input element stamps a weighted copy of the kernel into an accumulator, and the stamps sum. Note it is not a mathematical deconvolution — the encoder and decoder kernels are learned independently, so it does not invert anything.
The failure this produces
Compress-then-reconstruct gives you blobby, low-frequency masks. The high-frequency boundary detail was destroyed in the encoder and the decoder has no way to invent it.
Skip connections — the fix, and U-Net
Route each encoder stage's feature map directly across to the matching decoder stage. Two forms: additive residuals (ResNet/Inception — mainly a gradient and loss-landscape benefit) and concatenation (U-Net — the feature maps are stacked, so genuine high-frequency detail reaches the decoder). U-Net is a symmetric encoder–decoder with concatenated skips and a per-pixel softmax output. It remains competitive against transformer architectures, and domain variants like nnU-Net dominate biomedical imaging.
✦ Details that earn marks

Label vs one-hot encoding. F = 1 with integer labels is cheap; F = number of classes with one-hot is expensive but sometimes necessary. Usually label encoding, for compute. Don't confuse input channels C with output classes F — they are unrelated, and a custom loss is needed when they differ. Keep per-class scores per pixel — don't collapse to a max before the loss. Resize image and mask together. Low loss ≠ good mask, because per-pixel loss is averaged over an image dominated by easy background — which is exactly why segmentation is accepted on IoU/Dice.

◆ Multi-modal input, worth one line in a design answer

Nothing forces C = 3. Hyperspectral bands, X-ray, LiDAR, radar and ultrasonic all stack as extra input channels — an ADAS perception stack fuses them this way. Classical methods could not scale past 3-D feature spaces; this is the concrete reason deep learning took over.

5 · Object detection — the two-stage line Session 13

◆ The problem

Predict class and a bounding box, for an unknown number of objects, at unknown scales and aspect ratios, with occlusion and viewpoint change. The naive solution — sliding windows — sweeps a window over the image at many scales and aspect ratios and classifies each crop. It is correct and unusable: the candidate count explodes, almost all the computation is redundant, and the class balance is catastrophic (6 objects among 330 windows).

HOG templates and DPM
Build an average gradient-orientation template (e.g. of a pedestrian) and convolve it to get a response map. Breaks because: gradients are low/mid-level features with no semantics — mannequins fire, side profiles fail, scale is handled badly. DPM optimises the same idea with deformable parts. Pre-2012 this plateaued around 33–40% mAP on PASCAL VOC.
R-CNN
Idea: attack the class imbalance by proposing only ~2000 plausible regions with selective search (bottom-up merging of segmented regions — Gestalt grouping again), warp each to a fixed size, run a pretrained CNN, classify with per-class SVMs plus box regression. mAP jumps to ~54–58%. Breaks because: 2000 CNN forward passes per image (~47 s inference, ~84 h training); it is three disconnected stages so errors accumulate; and the proposals themselves are only ~35% accurate.
Fast R-CNN
Fixes the 2000 passes. Run the CNN once over the whole image, then project each region of interest onto the shared feature map (divide coordinates by the network stride) and RoI-pool it into a fixed 7×7 grid. One forward pass feeds two heads: softmax classification and box regression. Breaks because: proposals still come from selective search, outside the network — and RoI pooling quantises coordinates, so a fractional half-cell becomes several pixels of error at a 16× stride.
Faster R-CNN
Fixes the external proposals. A Region Proposal Network runs on the same shared feature map, using anchor boxes at fixed scales and aspect ratios, so proposals are learned end-to-end. RoI Align drops the rounding and keeps fractional coordinates. Inference falls to ~140 ms. Breaks because: it is still fundamentally two-stage — propose, then classify.
Mask R-CNN
Faster R-CNN plus a mask head — one network doing classification, detection and segmentation. The overlapping model: reach for it when a case study wants instance masks, not just boxes.
◆ The sentence that ties it together

"The region-proposal stage is the bottleneck — we never removed it, and that is where YOLO steps in." Each refinement moved work into the network and shared more computation; the two-stage structure itself was the last thing standing.

6 · YOLO — single-stage Session 13

◆ The idea

Delete the proposal stage. Divide the image into an S×S grid; each cell directly predicts an objectness probability, B bounding boxes with confidences, and conditional class probabilities P(class | object). Final score = P(object) × P(class | object). One forward pass, one network, box regression and classification as two heads on a shared stack.

Output tensor for PASCAL VOC: 7×7×(2×5 + 20) = 7×7×30. Then threshold on confidence and apply non-maximum suppression to collapse duplicates.

Why it matters
~7× faster than the fastest region-proposal network; 45 FPS against camera rates of 12–30 FPS. That is the difference between a system that can brake in time and one that cannot — the entire ADAS and drone argument.
The cost
"When you gain in speed, you lose out on accuracy and precision." Slightly lower mAP than Faster R-CNN, and in v1 each grid cell commits to one class — two different objects in the same cell means one is lost. Anchor boxes in v2 fix this (out of syllabus, but say the sentence).
Generalisation — an underrated point
YOLO transfers unusually well. Fine-tuned on ~100 annotated images it starts performing; it survives domain shift to artwork and Picasso-style images. R-CNN variants need substantial retraining. Failure mode: it detects "person" in a painting but cannot tell you it is a painting.
Tiers and tasks
nano / small / medium / large / extra-large — accuracy up, speed down, monotonically. The nano tier is the one you deploy on edge devices; it runs on CPU without a GPU. Task variants exist for segmentation, classification, pose/keypoints, and oriented bounding boxes for ADAS.

7 · Metrics, as theory Session 12 / 16

◆ Why accuracy is meaningless here

In detection, the overwhelming majority of candidate regions are background, so a model that predicts "nothing anywhere" scores above 90% accuracy. Class imbalance destroys accuracy as a measure. Everything below exists to route around that.

IoU
Area of overlap over area of union. It measures localisation quality on a 0–1 scale, and it is the gate that converts a prediction into a TP or an FP at a chosen threshold. Same idea for irregular masks, counted by pixels. Dice is its close relative; IoU relates to F1 in the same way — both combine overlap against total extent.
Precision and recall
Precision = of what I predicted, how much was right. Recall = of what existed, how much did I find. The asymmetry matters in design: a missed pedestrian is a fatality (recall-critical), a false alarm on a production line is a stopped line (precision-critical).
The ranking discipline
Sort detections by descending confidence, then walk down assigning TP/FP. One ground truth admits one true positive — a second detection on an already-matched object is a false positive even at IoU 0.9, because the higher-confidence detection claimed it. This rule is the single most-tested subtlety in the topic.
AP and mAP
Walking the ranked list traces a precision–recall curve, which comes out saw-toothed, so its area cannot be integrated directly. Interpolated precision — at each recall level take the maximum precision at that recall or beyond — straightens it. Average over 9 or 11 levels to get AP; average AP over classes to get mAP. Papers report mAP@0.5, mAP@0.75 and a small/medium/large breakdown, because one threshold hides where the model actually fails.

8 · Tracking Sessions 15–16

◆ The governing insight — say this in any tracking answer

Tracking exists to reduce latency, not to improve accuracy. Detection is expensive; a camera delivers frames faster than a detector can consume them. So you detect on one frame, track cheaply for the next several, and re-detect — keeping the interval under human persistence of vision (~1/16 s) so nothing perceptible is dropped. "We actually do not care about accuracy so much. We care about speed." An approximate position is enough, because its job is to tell the next detection roughly where to look.

This is why tracking stayed classical. Putting a neural network into the stage whose purpose is removing latency defeats the stage. DeepSORT and FairMOT exist and are out of syllabus — and out of industrial practice for exactly this reason.

Motion detection vs tracking
Motion detection is a binary trigger — something moved, sound the alarm. Tracking follows the object and yields speed, direction, trajectory. Different deliverables.
Background subtraction
Model the background, subtract, threshold to a foreground mask. Breaks under: illumination change, threshold sensitivity, camera motion (which invalidates the background model entirely), noise. Partly fixed by adaptive/temporal background models keyed to time of day.
Tracking by detection
Detect at t, detect at t+n, take displacement over time to get velocity — the speed-camera method, with image-to-world conversion via camera geometry. Breaks under: occlusion (the tunnel case), fast motion, camera shake, and the detector's own cost.

Optical flow — the core theory

◆ Understand it

Optical flow is the apparent motion of brightness patterns between frames — and "apparent" is load-bearing. A moving light source or a moving camera produces flow with no object motion at all. That gap between apparent and real motion is where most failure cases live.

Three assumptions: brightness constancy (a point keeps its intensity between frames), small motion (so the Taylor expansion can drop higher-order terms), spatial coherence (neighbouring pixels move together). Every failure mode is one of these three breaking.

The aperture problem: the brightness-constancy equation gives one equation in two unknowns (u, v) per pixel — unsolvable. Lucas–Kanade rescues it with spatial coherence: assume a whole window shares one (u, v), which turns one equation into an over-determined system solvable by least squares. Solvability requires the structure matrix to be invertible with both eigenvalues large — which is exactly the Harris corner condition. Both small = flat, no motion recoverable. One large = an edge, and you can only recover motion perpendicular to it. Both large = a corner, trackable. Hence Shi-Tomasi "good features to track."

Pyramidal LK: large displacements violate the small-motion assumption, so downsample until the motion is small, estimate there, and propagate the estimate back up, rescaling. Coarse-to-fine.

Families: Lucas–Kanade is local/sparse; Horn–Schunck is global/dense; Farnebäck is dense. Only LK is in syllabus. Applications: video stabilisation, super-resolution, activity recognition, facial-expression keypoints, visual SLAM.

Mean-shift tracking

◆ Understand it

The same mode-seeking algorithm as in segmentation, repurposed. Build a colour-histogram model of the target in a reference frame; in each new frame, climb the density in a local neighbourhood to find where that colour distribution now peaks. Strength: assumption-light relative to optical flow, simple, efficient, and it handles non-rigid objects — people, animals — that a rigid box tracker cannot. Breaks under: uniform intensity, abrupt illumination change, motion blur, occlusion, and distractors with the same colour.

Kalman filter

◆ Understand it

A recursive state estimator running predict → observe → correct. Predict the next state from a motion model; take a noisy measurement; blend them via the Kalman gain, which weights model against measurement according to their covariances. State = position, velocity and whatever physics matters; plus the state covariance, transition matrix, and Gaussian process and measurement noise.

What it buys you: it survives noise and gaps. Radar blips intermittently, wind pushes the drone, the target manoeuvres, the object goes behind a bridge — prediction carries you through the gap and correction snaps you back when a measurement returns.

Why no neural network: the system is linear, so a closed-form formulation suffices. There is no nonlinearity for a network to learn — and a network would add the latency you are trying to remove.

IMM — interacting multiple models — is a bank of Kalman filters, one per axis or per motion mode (constant velocity, constant acceleration), because a single model cannot cover both cruising and manoeuvring. How many filters is bounded by compute; their outputs are consolidated in one ECU before acting. The Kalman mathematics is out of syllabus — the predict/update cycle and this design reasoning are not.

9 · System design and deployment Sessions 13–17

◆ Convert latency into consequence

Never argue in FPS alone. Convert: at highway speed, detection latency becomes stopping distance. The ladder runs R-CNN → Fast R-CNN → Faster R-CNN → YOLO as roughly 1760 ft → 176 ft → 12 ft → under 2 ft, against a target inter-car gap of about 6 ft. Faster R-CNN at 140 ms is accurate and fatal. That reframing is what "latency removal" means in this course, and it transfers to drones, shop floors and surgical robots.

Edge deployment
Edge means constrained memory. Choose the nano tier, not the large one. PyTorch .pt weights are not optimised for edge — export to ONNX and flash that. Optimise for memory and trainable parameter count. Recover accuracy by fine-tuning the small model on domain data rather than by growing it. Targets: Jetson Nano, Intel OpenVINO, ARM, Raspberry Pi. Fallbacks if it still misses: a SqueezeNet-based custom implementation, then move the runtime from Python to C/C++.
Multi-camera: model vs data parallelism
Independent decisions → model parallelism, replicate the model per camera (a fleet of delivery drones). One joint decision over several views → data parallelism, coalesce the streams before predicting. For a car's ADAS, independent per-camera predictions are forbidden — front and rear views are evidence for the same judgement, so they must meet before the decision, not after. Accuracy is the same either way; the question is where the decision is made.
YOLO vs VLM
VLM when you lack training infrastructure, need natural language and multiple modalities, want speed of delivery, and accept that someone else owns the data. Its pipeline is pre-training → SFT → RLHF → DPO, measured in years. YOLO when the use case is localised, latency-bound, and you want the IP. The decisive argument is risk asymmetry: in natural language a hallucination is an annoyance; on a shop floor it costs life and limb. The mature answer is hybrid — YOLO detects, an agent above it reasons, wired through ROS topics: camera → YOLO → agent.
Data strategy
A population-versus-sample question, not a number. From scratch: ≥10,000, realistically ~1M images. With transfer learning: 100–200 can suffice, because the backbone has already seen the textures. And the honest caveat — 10M images may fail where 100 well-chosen ones work. Budget for an evaluation loop, not a fixed count.
Build vs buy
Library U-Net and detection implementations are predefined. Organisations — healthcare especially — write custom implementations and custom feature extractors because that is what they can own. Worth one line whenever a case study mentions a client's IP.

10 · The five chains, compressed

If you memorise nothing else, memorise these. Each is a complete answer skeleton.

ChainThe sequence, with the bottleneck that forces each step
ClassificationkNN (inference cost, pixel distance ≠ semantic distance) → linear (one template per class; no nonlinear boundary) → CNN (learned hierarchy) → ViT (no built-in priors, so data-hungry, but modality-agnostic)
Segmentation, classicalthresholding (no spatial info, modes arbitrary) → k-means (k by hand, hard assignment, linear boundaries, still no space) → GMM/EM (soft + elliptical, but k and the family by hand, slow) → mean-shift (adds (x,y) to the features and discovers k; dies in high dimensions) → deep learning
Segmentation, deepclassification CNN (outputs 1×1×F) → encoder–decoder (gets H×W×F but masks are blobby) → skip connections / U-Net (high-frequency detail bypasses the bottleneck)
Detectionsliding window (explosion + class imbalance) → HOG/DPM (no semantics) → R-CNN (2000 CNN passes, 3 disjoint stages) → Fast R-CNN (shared feature map + RoI pooling; proposals still external, quantisation error) → Faster R-CNN (RPN + RoI Align; still two-stage) → YOLO (deletes the proposal stage; loses some precision, one class per cell)
Trackingbackground subtraction (camera motion, illumination) → tracking-by-detection (too slow, occlusion) → optical flow / LK (aperture problem, three assumptions) → pyramidal LK (large motion) → mean-shift (non-rigid, colour-based) → Kalman/IMM (noise, gaps, manoeuvres)
✦ How to deploy a chain in an answer

A case study gives you a constraint. Walk the relevant chain from the top, naming the bottleneck at each step, and stop at the first method whose remaining weaknesses the constraint can tolerate. Then say explicitly what you gave up and how you bound it. That structure — walk, stop, justify the stop, price the compromise — fits every design question on this paper.
