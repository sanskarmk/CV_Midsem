Face detection vs recognition

Detection — is there a face, and where is the box (and optionally landmarks). Recognition / identification — whose face. Verification — is this the same person as the gallery template (1:1). Attendance system on a face image is the handout use case: detect → align (landmarks) → embed → match.

Viola–Jones (boosting)

T2 Ch 10.7. 2001, still the “why was it better than its predecessor?” story for faces.

Haar features
Rectangle differences (eye darker than cheek, etc.) computed in \(O(1)\) with an integral image.
AdaBoost
Pick a tiny set of those features as weak classifiers; the boosted combination is the detector.
Attentional cascade
Most windows are not faces. Early stages reject them with 1–2 features; later stages run only on survivors. That’s why it was real-time on 2001 CPUs.

Active appearance models (T2 Ch 10.5) fit a statistical shape+texture face for landmarks / expression — the classic alternative to modern landmark nets.

Face metrics (class notes in the handout)

  • IoU-based detection metrics — same TP rule as Session 12 (IoU ≥ 0.5).
  • TAR (true acceptance rate) / FAR (false acceptance) / FRR (false rejection) for verification.
  • TAR @ a specific FAR (e.g. TAR @ FAR = 10⁻³) — the operating point a bank actually cares about.
  • Top-K identification rate — is the right identity in the top K gallery hits.

Optical character recognition

Challenges: fonts, skew, blur, layout (tables, multi-column), handwriting, low resolution (number plates). Pipeline:

Layout / localisation
Find text regions — classical edges/contours, or a detector (YOLO), or a document transformer (LayoutLM, DiT).
Recognise
CNN+LSTM/CTC (Tesseract, EasyOCR) or a transformer decoder. Plate/invoice use cases in the handout.
Post-process
Language model / lexicon / regex (plate format) to fix visually ambiguous glyphs.

OCR metrics

MetricLevel
Character / word / sentence accuracyExact match at that granularity.
CER / WER via string edit distance (Levenshtein)\((\mathrm{sub}+\mathrm{ins}+\mathrm{del})/\mathrm{length}\). The standard OCR error rate.
mAP for text localisationDid we box the text regions (detection), independent of reading them.

Mini numerical — CER. GT = CAT, OCR = COT. One substitution, length 3 → \(\mathrm{CER}=1/3\approx33\%\). Word accuracy is 0 (the word is wrong) even though two characters were right — that’s why you quote both.

Key takeaways

◆ Remember these
  • Viola–Jones: integral image + AdaBoost + cascade. DNN faces: MTCNN / RetinaFace. Metrics: TAR @ FAR, top-K.
  • OCR: localise then read. Tesseract / EasyOCR / LayoutLM. CER = edit distance / length; mAP for boxes.
  • Use cases: attendance camera; number plate; invoice parsing.
