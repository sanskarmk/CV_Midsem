Edge Devices for Computer Vision

Run detection/segmentation on the camera, not in the cloud — because of latency, bandwidth, privacy and power. The comprehensive exam can ask a system-design / latency question here (the professor flagged exactly that). The job is to pick a board and a model that fit the wattage and the millisecond budget.

Why run vision on the device

  • Latency — a pedestrian detector on a car cannot wait for a round-trip to a server.
  • Bandwidth — 30 fps HD is a lot of uplink; sending boxes/embeddings is cheaper than video.
  • Privacy / offline — factory floors, attendance cameras, drones with no link.
  • Power / thermals — the constraint that actually picks the chip.

Handout LO4: “Design optimized computer vision solutions for resource-constrained edge devices that balance performance with hardware limitations.”

Models that actually fit

From the classification / detection lectures: MobileNet and Xception (depthwise-separable convs) exist specifically so a Pi / phone can classify. YOLO-nano / YOLO-tiny for detection. Quantise to INT8 (Coral, OpenVINO). Distil or prune a teacher Faster R-CNN if you only need the student on-device. SAM / huge ViTs stay in the cloud; a ViT-Tiny can edge if you have a Jetson Orin.

◆ Depthwise-separable in one line

A 3×3 conv on \(C\) channels is \(9C^2\) muls per pixel. Depthwise 3×3 (\(9C\)) + 1×1 pointwise (\(C^2\)) is why MobileNet is ~8–9× cheaper — the reason it shows up in the handout next to classification metrics.

Exam-style system design

Q. Warehouse camera must flag a person in a restricted bay in < 100 ms, no cloud, ~8 W budget. Sketch a stack.

Sensor
Fixed IP cam or Pi camera; 640×480 is enough for a person.
Board
Coral or Jetson Nano — Pi 4 CPU-only will miss 100 ms on a decent detector.
Model
INT8 YOLO-tiny / SSD-MobileNet. Not Faster R-CNN, not SAM.
Pipeline
Capture → letterbox → infer → NMS → if person ∩ bay polygon, GPIO alarm. No video uplink.
Quote
mAP @ 0.5 on a small in-domain set, latency on that board, watts at the wall.
Answer shape

Constraint → board class → model family → quantisation → on-device post-process → the three numbers (mAP, ms, W). That is the “latency removal / system design” question type from the comprehensive-exam briefing.

Key takeaways

◆ Remember these
  • Edge because of latency, bandwidth, privacy, power — not because it’s fashionable.
  • Menu: ESP32 → Pi → Intel+OpenVINO/Movidius → Jetson (CUDA/DeepStream) → Coral (INT8 TPU).
  • MobileNet / YOLO-tiny / INT8; quote FLOPs, memory, measured ms on named hardware.
