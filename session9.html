Image Classification

Given an image, pick a label from a finite set — cat, dog, truck, … This is the core recognition task everything later (detection, segmentation, tracking) builds on. The lecture path is data-driven: collect labelled images, train a classifier, evaluate on held-out data.

The classification problem

Assume a discrete label set, e.g. \(\{\text{cat}, \text{dog}, \text{cow}, \text{apple}, \text{tomato}, \text{truck}, \ldots\}\). A classifier maps an image \(x\) to a label \(y\). What actually matters in recognition (from the slides):

Learning method

kNN, linear classifier, neural net, deep net — how we turn features into a decision.

Representation

Raw pixels, SIFT, HOG, or deep-learned features. A better descriptor often beats a fancier classifier.

Data

PASCAL, CIFAR-10, ImageNet, COCO. Scale and diversity of labelled images dominate modern accuracy.

◆ Data-driven, not hand-coded

We do not write “if whiskers and pointed ears then cat.” We collect a database of images with labels, use ML to train a classifier, and evaluate it on images the model has never seen. CIFAR-10 (10 classes, 32×32 colour) is the running toy dataset in this lecture.

Train, validate, test

Split the labelled set into three disjoint piles. Never tune on the test set.

SplitUsed forTouched how often
TrainFit the model (remember examples, learn \(W,b\))Many times
ValidationChoose hyperparameters (\(k\), distance metric, learning rate…)Several times
TestEstimate generalisation — a single, final numberOnce, at the very end
▲ Hyperparameters are not learned

Choices like \(k\) and the distance metric are set by us, not by gradient descent. The methodology is: train the model, validate to pick hyperparameters, test once to report generalisability. Peeking at test accuracy while tuning is cheating — the test number stops meaning “unseen data.”

Bag of visual words

Before deep nets, the classic pipeline turned an image into a histogram of “visual words” — the same idea as a bag-of-words document classifier, but with image patches instead of English words.

Extract local features
Detect keypoints (SIFT, Harris, dense grid) and describe each patch as a vector.
Build a codebook
Run k-means on a huge pool of descriptors from the training set. The \(K\) cluster centres are the visual words.
Quantize
Assign every descriptor in an image to its nearest visual word.
Histogram
Count word occurrences → a \(K\)-D vector. Classify that vector (SVM, kNN, linear). Optionally add a spatial pyramid so layout isn’t totally thrown away.
◆ What it throws away, what it keeps

BoW is invariant to the order of patches (a cat is a cat even if you scramble parts) and cheap to match. The cost: it discards geometry. Two very different scenes can share the same word counts. That’s why later methods (HOG grids, CNNs, ViTs) keep spatial structure.

Nearest neighbour and kNN

Train: remember every training image and its label — \(O(1)\) “learning.” Predict: find the closest training image (or the \(k\) closest) and copy its label (majority vote).

Distance is a hyperparameter. Two common choices on flattened pixel vectors \(x, z \in \mathbb{R}^D\):

\[ L_1:\quad d_1(x,z)=\sum_i |x_i-z_i| \qquad\qquad L_2:\quad d_2(x,z)=\sqrt{\sum_i (x_i-z_i)^2} \]
TrainingTesting (N train, M test)
kNN\(O(1)\)\(O(MN)\) — compare every test image to every training image
What we actually wantSlow is OKFast — a deployed classifier must answer in milliseconds
▲ Why kNN fails on raw pixels

CIFAR-10 1-NN on raw pixels is only ~38% (chance is 10%). Pixel \(L_2\) thinks a shifted cat is far from itself, and a blue car may be “closer” to a blue truck than to a red car. You need a representation that cares about content, not camera pose and colour cast — which is exactly why SIFT/HOG and then CNNs exist.

Worked numerical — kNN

Q. Training points: \(A=(1,1)\) cat, \(B=(2,1)\) cat, \(C=(3,4)\) dog, \(D=(6,2)\) dog. Query \(q=(2,3)\). Using \(L_2\) distance, classify with \(k=1\) and \(k=3\).

Distances
\(d(q,A)=\sqrt{1+4}=\sqrt{5}\approx2.24\); \(d(q,B)=\sqrt{0+4}=2\); \(d(q,C)=\sqrt{1+1}=\sqrt{2}\approx1.41\); \(d(q,D)=\sqrt{16+1}=\sqrt{17}\approx4.12\).
\(k=1\)
Nearest is \(C\) (dog) → dog.
\(k=3\)
Nearest three: \(C\) dog, \(B\) cat, \(A\) cat. Majority = cat.
Answer

\(k=1\) → dog; \(k=3\) → cat. Same query, different \(k\), different label — which is why \(k\) is chosen on the validation set, not the test set.

Linear classifiers — a parametric score

Instead of storing the whole training set, learn a weight matrix \(W\) and bias \(b\) so a score function \(f(x,W)=Wx+b\) produces one score per class. The predicted label is \(\arg\max_c f_c\). Geometrically each class is a hyperplane: \(x\cdot w + b \ge 0\) on the positive side.

Each row of \(W\) is a template for that class. Scoring is template matching: how well does the image correlate with the “cat template,” the “car template,” …

◆ Why not just count misclassifications?

Number of mistakes is discrete (can’t break ties, no gradient). We want a loss that (i) is continuous, (ii) encourages a margin so we generalise, and (iii) works for more than two classes.

Loss, softmax and cross-entropy

A loss (objective / cost) measures how unhappy we are with the scores given the true labels. Training = find \(W,b\) that minimise the loss.

Softmax turns scores \(s\) into a probability distribution:

\[ p_c = \frac{e^{s_c}}{\sum_j e^{s_j}} \]

Cross-entropy loss for true class \(y\) is \(L = -\log p_y\). If the model is confident and correct (\(p_y\to1\)), loss \(\to 0\); if it puts almost no mass on the true class, loss \(\to+\infty\). SVM / max-margin losses were popular; cross-entropy is the default classification loss now.

Worked numerical — softmax + cross-entropy

Q. Three-class scores \(s=(2.0,\,1.0,\,0.1)\), true class is class 0. Compute softmax probabilities and the cross-entropy loss.

Exponentials
\(e^{2.0}=7.389,\ e^{1.0}=2.718,\ e^{0.1}=1.105\). Sum \(=11.212\).
Softmax
\(p=(0.659,\,0.242,\,0.099)\).
Cross-entropy
\(L=-\log 0.659 \approx 0.417\).
Answer

\(p\approx(0.66,\,0.24,\,0.10)\), \(L\approx0.42\). If the true class had been class 2 (\(p=0.099\)), loss would be \(-\log 0.099\approx 2.31\) — much unhappier, as it should be.

Key takeaways

◆ Remember these
  • Classification = map image → discrete label. Method + representation + data all matter.
  • Train / validate / test: hyperparameters on val, test set used once.
  • BoW: quantize local features to a codebook, classify the histogram.
  • kNN: train \(O(1)\), test \(O(MN)\) — the wrong complexity for deployment; raw-pixel kNN is weak.
  • Linear classifier: \(f=Wx+b\), rows of \(W\) are templates. Softmax + cross-entropy is the standard loss.
  • Handout DNNs for this module: MobileNet, Xception (depthwise-separable — see edge devices).
  • Use cases: fruit sorting and apparel type via transfer learning — freeze an ImageNet backbone (MobileNet/Xception), replace the last layer, fine-tune on your small labelled set (Lab 5 in the handout).
  • Extra classification metrics (handout): Top-K (true class in the top K scores), macro-P/R/F1 (unweighted mean over classes — fair when classes are rare), Brier score (mean squared error of predicted probabilities — punishes overconfidence), plus FLOPs / memory / inference time on named hardware.
