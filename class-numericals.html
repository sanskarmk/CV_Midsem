N1 · Convolution output size Session 12 · 00:50:43

Q. A \(7\times7\) input is convolved with a \(3\times3\) kernel, padding \(P=0\) (valid), stride \(S=1\). Output dimension?

Formula (dictated 00:52:02)
\(\text{out} = \left\lfloor \dfrac{N - K + 2P}{S} \right\rfloor + 1\)
Substitute
\(\left\lfloor \dfrac{7 - 3 + 0}{1} \right\rfloor + 1 = 4 + 1 = 5\)
Both axes
Shrink identically → \(5\times5\).
Answer

5 × 5

✦ In his words · 00:53:26

“7 minus 3, 4, 4 by 1 is 4, 4 plus 1 is 5. So the end dimension of this would be 5 cross 5 from convolution operation.” The VGG trace he runs next (224 → 112 → … → 32) halves via 2×2 max pooling at stride 2, not via the convolutions.

N2 · Transpose convolution, 3×3 → 5×5 Session 12 · 01:03:12

Two questions in one: which stride and padding get me from 3 to 5, then what does the arithmetic actually do.

Q (part A). Input \(i=3\), kernel \(K=3\), required output \(O=5\). Find \(S\) and \(P\).

Formula (01:04:10)
\(O = (i-1)\cdot S - 2P + K\)
Substitute
\(5 = (3-1)S - 2P + 3 \;\Rightarrow\; 2 = 2S - 2P \;\Rightarrow\; 1 = S - P\)
Choose
\(P=0\) — “padding is introducing data that does not exist” — hence \(S=1\).
Verify
\((3-1)(1) - 0 + 3 = 5\) ✓
Answer

S = 1, P = 0

Q (part B). Input \(\begin{bmatrix}1&2&3\\4&5&6\\7&8&9\end{bmatrix}\), kernel \(\begin{bmatrix}1&0&1\\0&1&0\\1&0&1\end{bmatrix}\). Perform the transpose convolution.

Initialise
A \(5\times5\) accumulator of zeros. Convolution slides one kernel over the image; transpose convolution reverses it — each input element stamps a weighted copy of the whole kernel into the accumulator.
Stamp element 1
at (0,0) → \(1\times\)kernel into rows 0–2, cols 0–2: 1 0 1 / 0 1 0 / 1 0 1
Stamp element 2
at (0,1) → \(2\times\)kernel one column right, rows 0–2, cols 1–3: 2 0 2 / 0 2 0 / 2 0 2
Repeat & sum
All nine elements, each offset by \(S=1\); add the nine intermediate matrices cumulatively.
Final 5 × 5 output
12423
461286
814251612
41218146
781689
Answer

The \(5\times5\) matrix above. Check: \(\sum\text{out} = \sum\text{in}\times\sum\text{kernel} = 45\times5 = 225\) ✓

⚠ Flag

He stamps only the first two elements on the board, then says “you will continue to do it for all pixels… in the end you will get a 5 cross 5 output.” The completed matrix above applies his own rule to the remaining seven — it was never read out in class. He also mis-speaks the first stamp row as 1 1 1 and a student corrects him to 1 0 1 at 01:08:23.

N3 · IoU by box area Session 12 · 01:33:04

Q. Ground truth (green) spans \(x: 50\to250,\; y: 50\to200\). The prediction (red) overlaps it over a \(180\times120\) region. Find IoU.

Area of overlap
\(180 \times 120 = 21{,}600\)
Ground-truth area
\((250-50)\times(200-50) = 200\times150 = 30{,}000\)
Union
\(A_{gt} + A_{pred} - A_{\cap} = 37{,}800\) — the overlap must be subtracted once, because adding the two areas counts it twice.
Divide
\(\text{IoU} = 21{,}600 / 37{,}800 = 0.571\)
Answer

IoU ≈ 0.57 — above the 0.5 accept threshold, but he calls it unsatisfactory: “you would want this overlap to be somewhere close to 0.95.”

✖ The mistake he names · 01:36:00

“This is where most of you make mistakes within your exam. You did not subtract the area of overlap, because you are adding it twice.”

⚠ Flag

The prediction box's own corners are garbled on tape (“70… 250… 17 minus 250”). Only three numbers survive cleanly: 21,600, 37,800, 0.57. Back-solving, the prediction area must be \(37{,}800 + 21{,}600 - 30{,}000 = 29{,}400\). He mentions the Dice coefficient here and defers it; it is never worked.

Q. Ground truth: bottom-left \((1,1)\), top-right \((6,5)\). Prediction: bottom-left \((2,2)\), top-right \((8,7)\). Accept threshold IoU > 0.5. Accept or reject?

Intersection corners
\(x: \max(1,2)=2 \to \min(6,8)=6\); \(y: \max(1,2)=2 \to \min(5,7)=5\)
Intersection area
\((6-2)\times(5-2) = 4\times3 = 12\)
Ground-truth area
\((6-1)\times(5-1) = 5\times4 = 20\)
Prediction area
\((8-2)\times(7-2) = 6\times5 = 30\)
Union
\(20 + 30 - 12 = 38\)
Divide
\(\text{IoU} = 12/38 = 0.3158\)

N7 · Mean-shift mode seeking, 1-D Session 16 · 00:14:51

Q. Points \(\{20, 22, 27\}\), bandwidth \(h=6\), seed \(X_0=20\), window \([X-h,\, X+h]\). Find the mode.

Iteration 1
Window \([20-6,\,20+6] = [14,\,26]\) → captures \(\{20,22\}\); 27 falls outside. \(X_1 = (20+22)/2 = 21\)
Iteration 2
Window \([15,\,27]\) → captures \(\{20,22,27\}\). \(X_2 = (20+22+27)/3 = 69/3 = 23\)
Iteration 3
Window \([17,\,29]\) → captures all three. \(X_3 = 69/3 = 23\)
Stop
\(X_3 = X_2\) → the mean has stopped shifting; the mode is reached.
Answer

Mode = 23, after 3 iterations. For 2-D, run the identical loop on \(x\) and \(y\); the converged point is the centre of mass of the region of interest — the tracked window for the next frame.

⚠ Flag

At 00:19:29 the transcript renders iteration 3 as “20 plus 22 plus 23 divided by 3”. That is a transcription slip — \(20+22+23=65\), giving 21.67, not the 23 he and the class agree on. The intended sum is \(20+22+27=69\).

✦ In his words · 00:19:48

“Do you see this? X2 is equal to X3. So it tells the mean shift algorithm that basically you have reached the mode.”

N9 · Lucas–Kanade least squares & solvability Session 15 · 01:16:03

Symbolic rather than arithmetic, but it is set up as a solve and it reuses the corner-detection matrix he named as examinable.

Q. The optical flow constraint gives \(I_x u + I_y v + I_t = 0\) — one equation, two unknowns. Using a \(5\times5\) window, solve for \((u,v)\) and state when it is solvable.

Spatial coherence
Assume every pixel in the window shares the same \((u,v)\): \(5\times5 = 25\) equations, 2 unknowns.
Stack
\(A\,d = b\), with \(A\): 25×2, \(d\): 2×1, \(b\): 25×1 — an over-determined system.
Least squares
\(A^{\mathsf T}A\, d = A^{\mathsf T}b\)
The matrix
\(A^{\mathsf T}A = \begin{bmatrix}\sum I_x^2 & \sum I_xI_y\\ \sum I_xI_y & \sum I_y^2\end{bmatrix}\) — the second-moment matrix, identical to Harris corner detection.
Solvability
\(A^{\mathsf T}A\) must be invertible and both eigenvalues large.
ConditionRegionFlow estimate
\(\lambda_1,\lambda_2\) both smallFlat / texturelessNo intensity variation → no motion recoverable
\(\lambda_1 \gg \lambda_2\)EdgeAperture problem — only normal flow
\(\lambda_1,\lambda_2\) both largeCornerTrackable — this is what you pick
Answer

\(d = (A^{\mathsf T}A)^{-1}A^{\mathsf T}b\), valid at corners only — which is why patches are selected with Harris / Shi-Tomasi “good features to track” rather than at random.

✦ In his words · 01:19:20 – 01:20:18

“If you remember your corner detection, we had a similar matrix… A transpose A should be invertible, and at the same time eigenvalues should not be too small. Neither should one be larger than the other one — both should be large, then only we can track it.”

Carry-forward rules he repeats across every metrics numerical

RuleWhat it means
Subtract onceUnion = A + B − intersection. Adding the two areas without removing the double-counted overlap is the error he names explicitly.
Rank firstStep one of every AP question is sorting detections by descending confidence. Every TP/FP verdict downstream depends on that order.
One GT, one TPA second detection on an already-matched ground truth is a false positive even at IoU 0.9. Decide on confidence and IoU alone — “no other considerations to be taken.”
9 vs 11 point9-point runs recall 0.1 → 0.9 and divides by 9. 11-point runs 0.0 → 1.0 and divides by 11. Same rule: max precision at recall ≥ the level.
Ask for IoUIf a question gives boxes but no IoU or confidence values, ask the examiner rather than eyeballing — he flags his own slides as unreliable on this.
Recall denominatorAlways the number of ground truths, never the number of detections.

Examinable, but never worked on this footage

Named as expected numerical topics but taught pre-midsem or only conceptually, so there is no worked solution to reconstruct from the recordings. Use Numericals — Step by Step for the method on each.

◆ Histogram equalization

Named at 01:45:30 in the optical-flow session. The classical-segmentation session touches histograms at 00:33:28 for thresholding, but never runs the equalization arithmetic. Work it from the pre-midsem slides — CDF mapping over a small grey-level table.

◆ Corner detection

Named at 01:45:34 and reused symbolically in N9. Pre-midsem material. The makeup-paper dispute in the image-classification session confirms Harris separates flat / edge / corner only — strong/weak edge thresholding belongs to Canny.

◆ k-means clustering

Named at 01:21:36 in revision. The classical-segmentation session covers it conceptually at 00:47:15 – 00:58:05 (centroid init → assign → update → converge) and demos it in OpenCV, but no hand-worked centroid iteration is done. Expect it in the same shape as N7 — a short assign-and-recompute loop.

✖ Explicitly excluded

GMM / EM derivations and numericals — “I do not expect any of the numerical results from this” (01:19:16). The 1999/2002 mean-shift papers — “Will it come in the exam? Absolutely not” (01:55:53). Kalman filter mathematics — only the predict → update cycle is examinable. Transformer/ViT derivations and YOLO v2 anchor boxes are also out.

◆ Exam shape

40-mark paper, 6–7 questions, variable marks per question (4–10). 10–20% pre-midsem, 80–90% post-midsem. Open book, watermarked slides only. Numericals will be simplified and concept-grounded rather than straight reproductions of these slide examples.
