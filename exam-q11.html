Sliding Windows, R-CNN Family & YOLO

Sessions 13–14. High-probability 10-marker: class imbalance, the upgrade ladder, YOLO v1 grid. Anchors (YOLOv2) are out of syllabus.

📄 Question

Q11(a) A \(64\times48\) image is scanned with a \(16\times16\) window, stride 8. How many windows? If 4 contain an object, what is the positive rate? Why are region proposals used? 3M

Q11(b) For each step R-CNN → Fast R-CNN → Faster R-CNN, state what was slow and what the successor fixed. What does Mask R-CNN add? 4M

Q11(c) YOLO v1 uses a \(7\times7\) grid, 2 boxes per cell, 20 PASCAL classes. How many numbers does the network emit? Why is it faster than Faster R-CNN, and what do you give up? 3M

Solution — Q11(a)

\[ n_x=\left\lfloor\frac{W-w}{s}\right\rfloor+1,\quad n_y=\left\lfloor\frac{H-h}{s}\right\rfloor+1 \]
Count
\(n_x=(64-16)/8+1=7\), \(n_y=(48-16)/8+1=5\) → \(7\times5=\mathbf{35}\) windows.
Class imbalance
\(4/35\approx11\%\) positives. The lecture duck: \(6/330\approx1.8\%\) — “lots of unnecessary negatives.”
Proposals
Selective Search / RPN scores ~2000 likely object regions instead of every slide, so the classifier is not drowned in empty water / sky.
Answer

35 windows, ~11% positive. Sliding windows explode (scale × aspect × position); proposals exist to stop scoring empty background. Accuracy is the wrong metric.

Solution — Q11(b)

MethodBottleneck it inheritedFix
R-CNN~2000 crops, CNN run per crop (~47 s/image, VGG16); three separate losses—
Fast R-CNNStill Selective Search (~2 s) on CPUCNN once per image + RoI pool; single multi-task loss
Faster R-CNN—RPN learns proposals on the shared map; proposals nearly free

One-liners

Fast vs R-CNN: share convs. Faster vs Fast: learn the proposals. Mask: add a mask. SSD is the other one-stage family (default boxes on several maps).

Solution — Q11(c)

Each cell predicts \(B\) boxes of 5 numbers \((x,y,w,h,\mathrm{conf})\) plus \(C\) class scores:

\[ 7\times7\times(2\times5 + 20) = 49\times 30 = \mathbf{1470} \]
Answer

1470 outputs, one forward pass — no proposals. ~7× faster than Faster R-CNN, lower mAP / worse on small objects. Robotics favourite. YOLOv2 anchors are not in syllabus — stop at the 7×7, 2-box grid.

Practice questions

P11.1 Image \(H=600, W=800\), feature map \(6\times8\). Box \((x,y,w,h)=(50,150,250,350)\). Where does it land on the feature map? 2M

Scale \(600/6=100\) in \(y\), \(800/8=100\) in \(x\).

Answer

\((0.5,\ 1.5,\ 2.5,\ 3.5)\) on the feature map, then RoI-pooled to \(7\times7\). (Slide geometry.)

P11.2 Lecture duck: 330 windows, 6 positives. If a classifier labels every window “duck”, precision? If it labels none, accuracy (approx)? 2M
Answer

Always-duck: \(P=6/330\approx1.8\%\), \(R=100\%\). Never-duck: accuracy \(=324/330\approx98\%\), recall \(=0\). That is why we use P/R and mAP, not accuracy.

P11.3 Multiclass vs multilabel in detection. One use of mean-shift as a detector. Skin detection in one line. 2M
Answer

Per box: multiclass (softmax). Per image: multilabel (many objects). Mean-shift on a colour map → modes = centres. Skin: HSV/YCbCr (or small CNN) pixel classifier as a cheap face/hand proposal.

P11.4 YOLO vs Faster R-CNN — two bullets. 2M
Answer

Two-stage (Faster): propose then classify — slower, usually more accurate, better small objects. One-stage (YOLO/SSD): dense grid — real-time, a bit less precise. Exam pivot is almost always this sentence.
